# Steps 02–03 — semantic-first space construction
Updated: 2026-10-28 (America/New_York).
Authority: user's October 27–28 clarification and subsequent discussion.
Status: current research direction and pilot prerequisites; no embedding model, boundary constructor, generation algorithm or pilot result is adopted here.

## 1. Concept and continuity

Construct a focused but flexible space of architectural strategies from a small set of brief-responsive LLM seeds. The region must include uninstantiated possibilities; it is not the seed archive or a plot of observed cases. Later exploration is intended to operate primarily within this region. Restriction is the mechanism, not a defect to dismiss by invoking a global optimum. Boundary refinement and reopening remain possible.

> **Superseded 2026-10-29:** the boundary is joint. The axes locate and bound exactly; the embedding supplies meaning relations, steering, novelty checks and cross-checks on carried traits; membership requires both. See [CORE_CONTRIBUTION](CORE_CONTRIBUTION.md). Earlier wording: the user's direction was to define the boundary primarily through semantic embeddings of strategic descriptions, with the nine-axis framework helping ground, audit and strengthen it. This supersedes an axis-envelope-first constructor as the immediate direction. It does not establish that embedding distances already capture architectural meaning or creativity.

Preserve ME's strategic representations, benchmark, realization/checking experience and experimental history. Develop a method/tool for existing LLMs; do not build a new LLM or claim access to its internal reasoning/latent space.

## 2. Decisions and their authority

- **Scope:** focus development on Steps 02 and 03. Later stages remain a revisable broad workflow; do not fix search engines, feedback rules, narrowing thresholds, realization budgets or stopping details yet.
- **Seed count:** Step 02 can proceed without finding an optimum. Five existing parents provide continuity for a pilot, not a permanent count or proven optimum.
- **Partial strategies:** the user welcomed exploration through partial commitments and blanks as promising. Initial seeds should communicate coherent organizing strategies. Exact completeness requirements and completion mechanisms remain open. Blanks alone are not demonstrated coverage.
- **Nine axes:** keep the established framework consistent. Consider evolution only when a concrete failure emerges; defer that separate complication.
- **Expansion admission:** provisionally admit an outside candidate when it introduces an explainable, brief-relevant strategic possibility beyond the current region. Demonstrated superiority or dimensional feasibility is not required first. Record conflicts and uncertainty.
- **Fixed/free choices:** investigate retaining some commitments while other decisions vary over allowed alternatives/ranges. This is a promising mechanism, not a frozen family schema.
- **Access:** advanced-model interaction must work through manual chat batches. Prefer code and, where justified, local models for repeatable work. Avoid advanced-model calls per candidate.
- **User ownership:** explain and test the conceptual mechanism before committing an opaque implementation.

## 3. Five development tasks

### Task 1 — consistent Step 02 records
Each seed needs:
1. Explicit strategic decisions, sufficient to locate/check what it actually commits to.
2. An overall semantic description: intention, organizing choices, expected consequences, trade-offs and unresolved matters.
3. Nine-axis descriptors with versioned extraction rules and unknowns retained.
4. Evidence links distinguishing source statements from inferred intentions or predicted benefits.

Consistency means comparable information, not identical schemes across runs. Avoid silently adding architectural intentions to existing records. Expected consequences are hypotheses until tested.

The legacy named framework is: program_organization, mass_count, distribution_balance, topology, loading, mean_height, height_articulation, vertical_organization, geometric_character. Preserve the distinction between these nine named descriptors and the earlier proof-check encoding G36/V9/C36 (81 coordinates). Legacy extraction details are not automatically suitable for new records; missing values must not receive silent defaults.

### Task 2 — choose and validate the embedding representation
Start by evaluating existing embedding models. Fine-tuning/training is contingent on a diagnosed failure, adequate data and a justified benefit; it is not a prerequisite.

Compare an overall-description embedding with a small set of aspect-specific descriptions/embeddings. Aspects can arise from brief concerns such as inclusion or public access; they are not new named ME axes. Use a fixed encoder/configuration, stable descriptions and traceable original text. Avoid repeated generic brief text dominating comparisons.

An external embedding model supplies a comparison representation, not a copy of an advanced LLM's internal possibility space.

### Task 3 — establish the semantic/axis relationship
Link both representations through the same strategy:
semantic intention -> supporting strategic decisions -> affected nine-axis descriptors.

This is a many-to-many relationship, not an assumed reversible coordinate conversion. Different organizations can pursue the same intention; the same organization can support different intentions. Five seeds are insufficient to justify a general learned translator or nine disentangled directions in embedding space.

Axes can audit organizational differences, check explicit implementation locks and diagnose semantic/structural disagreement. Do not require all semantic neighbors to be close on all axes.

### Task 4 — define and validate joint membership and expansion
Specify exactly how semantic relevance, axis evidence, retained commitments and permitted variation determine membership. A rule must cover unseen possibilities, not only label existing seeds.

Candidate comparison, NOT an adopted constructor:
- Overall semantic neighborhoods around seeds.
- Conditional neighborhoods preserving selected aspects while allowing others to vary.

Calibrate against explicit comparison examples; do not choose unexplained cosine thresholds. Five seed points alone do not identify the correct region. Defer a convex hull, fitted density or a single weighted semantic-plus-axis distance until its assumptions are justified.

Freeze the current region before testing whether a candidate is outside it. Semantic spread, a new coordinate value and useful architectural expansion are different observations.

Provisional admission updates a versioned region explicitly; newly generated points must not silently recenter it and cause unlimited expansion.

### Task 5 — provide a minimal unseen-strategy generator
Boundary rules and embeddings do not by themselves generate strategies. Establish how code/local models/manual advanced-model batches propose complete or partial candidates, describe them faithfully and locate/check them in both spaces.

A first candidate is code-generated explicit variations under declared commitments, followed by embedding-based membership checks. This remains operator-limited; introducing a new organizing concept may need LLM/user input. Do not present this proposal as solving open-ended creativity or arbitrary-vector decoding.

## 4. Fixed and flexible commitments

Distinguish:
- **Implementation lock:** retain an arrangement, e.g. academic and special education remain in the same mass.
- **Semantic lock:** retain an intention, e.g. support academic participation, while potentially changing the implementation.

The second requires interpretation and later evidence. A claimed intention is not proof of its effect. Whether to test both kinds separately is an unanswered assistant recommendation, not a user-confirmed decision.

Flexible decisions can have allowed alternatives, ranges or explicit unknowns. Confidence in extraction, strength of preference, feasibility evidence and probability of a beneficial effect are different quantities. An LLM confidence percentage or embedding similarity is not a calibrated probability.

Retaining an aspect need not freeze a numerical embedding coordinate. Test whether candidates remain similar under retained aspects while varying on others. Unknowns are not unrestricted validated alternatives.

## 5. Pilot prerequisites and proposed sequence

This is a proposal to finalize, not an experiment already run or a request for additional generation rounds.

1. Reuse the existing brief and five parent seeds; audit missing information before supplementing it.
2. Establish comparable records and source-linked semantic descriptions.
3. Test representations on paraphrases, changed relationships/intentions with similar wording, different implementations of a shared intention, and generic but irrelevant school descriptions.
4. Compare overall versus aspect-conditioned semantic relationships on the same examples. Use axis evidence to explain disagreements.
5. Only then freeze candidate membership rules and test unseen completions and controlled outside expansion at matched budgets.

Exact structural measurements: record consistency, duplicate signatures, membership and explicit decision changes.
Separate judgments: brief relevance, preserved intention, meaningful strategic difference and usefulness.
Track review, setup, transfers, model calls and time. Larger embedding spread is not a coverage/quality certificate. Do not claim universal boundary sufficiency, global optimality or physical feasibility.

Earlier suggestions of 12 completions/six probes and one-versus-two edits are practical assistant proposals, not agreed sample sizes or validated edit metrics.

## 6. Research: support, limits and proposed application

These are primary sources examined in the discussion. They support components, not the complete ME2.0 method.

- **C-STS: Conditional Semantic Textual Similarity (EMNLP 2023):**
  https://aclanthology.org/2023.emnlp-main.345/
  Similarity depends on the aspect of interest; the tested models find the task challenging. Supports testing conditional relevance rather than using only global similarity.
- **Linguistically Conditioned Semantic Textual Similarity (ACL 2024):**
  https://aclanthology.org/2024.acl-long.64/
  Identifies annotation/condition ambiguity and uses question answering to expose aspect-specific information before comparison. Its section 4 also documents extraction errors and opposite meanings with high embedding similarity. Suggested application: source-grounded aspect descriptions, explicit unknowns and contrast checks; not automatic semantic truth.
- **AspectCSE (RANLP 2023):**
  https://aclanthology.org/2023.ranlp-1.113/
  Trains aspect-based embeddings, including multiple aspects. Supports aspect-sensitive representation; its trained retrieval experiments do not establish zero-shot architectural transfer.
- **INSTRUCTOR / One Embedder, Any Task (Findings ACL 2023):**
  https://aclanthology.org/2023.findings-acl.71/
  Task instructions condition embeddings using an already trained model. Supports testing suitable existing instruction-sensitive encoders, not assuming arbitrary models follow instructions or that architecture is solved.
- **SemAntoNeg (BlackboxNLP 2022):**
  https://aclanthology.org/2022.blackboxnlp-1.20/
  Negation/antonym paraphrase distinctions expose weaknesses in tested sentence embeddings. Motivates architectural contrast examples, not a claim that every current encoder fails.
- **Text Embeddings Reveal (Almost) As Much As Text (EMNLP 2023):**
  https://aclanthology.org/2023.emnlp-main.765/
  Trained embedding inversion is possible for particular encoders/settings. It does not demonstrate that interpolated strategy vectors decode to coherent new architecture. Neither universal invertibility nor universal impossibility is claimed.
- **Ollama official embeddings documentation:**
  https://docs.ollama.com/capabilities/embeddings
  Local embedding computation can be automated separately from advanced chat-model access. No local installation or model benchmark is claimed.

Earlier relevant construction precedents:
- Garcia and Leitao, *Navigating Design Spaces* (2022), DOI 10.1177/14780771211073119: selected examples define subspaces within an existing generative system; does not supply our generator.
- Glover, Laguna and Marti, *Fundamentals of Scatter Search and Path Relinking* (2000): attribute-based paths and extrapolation; architectural operators and relevance remain our responsibility.
- Wan et al., CASMOPOLITAN (ICML 2021): categorical adjustable trust regions with objective-driven updates; not a semantic constructor under changing briefs.
- IDEA (2025 preprint v1), https://arxiv.org/html/2506.10587v1: constraints, explicit search and execution; manually predefined spaces are an acknowledged limitation.
- Luminate (CHI 2024), https://arxiv.org/html/2310.12953v3: dimensions, structured LLM generation and human exploration; not proof of code-only space construction.

## 7. Prior diagnostic findings and limits

The October 27 concept review executed grouping-only logic checks on the existing five parent organizations. With gym/dining one indivisible unit and exactly three nonempty anonymous masses, the small declared reference contains 966 partitions.

Different rules admit 8 (consistent observed-value envelope), 37 (one-pass union of all seed-pair shortest-path intervals), or 63 (one-move seed neighborhoods). Iterated geodesic closure admits all 966. The graph move transfers one unit between existing masses; floors, links, geometry and semantics are absent.

Independently recombining 16 varying co-location bits yields 65,536 patterns but only eight structurally consistent three-mass organizations within that observed-value envelope. A separate nine-binary-variable example shows that all 84 three-variable projections can admit a point excluded by the joint relation.

These are finite formalization diagnostics, not architectural quality tests, an adopted constructor, a requirement to enumerate production space, or validation of embedding boundaries. Their lesson is to specify membership, dependencies and update behavior explicitly.

The separate completed seed-count/A/B findings remain governed by [their scope audit](STEP02_03_PROOF_CHECK_FINDINGS.md). No new generation, embeddings, fine-tuning or pilot performance is claimed by this documentation update. Raw responses and report packages are not published here.
